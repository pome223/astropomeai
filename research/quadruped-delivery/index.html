From Agent Judgment to Verified Return: A Governed Quadruped Delivery Study

Two MuJoCo Go2 scenarios distinguish mission-level reasoning from local obstacle response

Astropome AI22 October 20266 min readNot peer reviewed

Abstract

A robot configured for AI supervision need not call a language model for every disturbance. MissionOS tests this distinction through two recorded Unitree Go2 deliveries in MuJoCo. A temporary passage closure elicited two actual DeepSeek judgments: wait, then reroute to the same approved destination. Both passed Rules checks and the second was linked to verified navigation. A separate moving-obstacle run completed through local yielding with zero LLM judgments. Both verified simulated receipt, return, and a five-second terminal hold. The study establishes an integrated simulator workflow and explicit responsibility boundaries; it does not establish physical delivery, perception-based navigation, or superiority over a matched rules comparator.

Keywords / Unitree Go2 · Mission supervision · DeepSeek · MuJoCo · Quadruped navigation · Outcome verification

1. Introduction

Autonomous delivery combines decisions operating at different timescales. Joint control maintains gait, navigation follows a route, local avoidance handles an immediate conflict, and mission supervision decides whether an interruption justifies waiting, replanning, or returning undelivered. Assigning all of these behaviors to “the AI agent” obscures both engineering responsibility and experimental evidence.

The MissionOS Go2 study makes that separation visible. It reports one saved moving-obstacle run and one saved temporary-closure run, both configured for Agent supervision. Only the closure run invoked the language model. The records connect operator approval to bounded execution and later verification, rather than treating a selected UI setting as evidence of inference. [1]

2. Methods: Layered Control in a Known Office

The mission travels from reception to Meeting Room A, records a simulated recipient receipt, returns to reception, and verifies a five-second terminal hold. Approval binds the destination, scenario, input hashes, Agent configuration, and action envelope. The installed CLI workflow checks rejection before approval, then invokes the normal approval and run commands.

Navigation uses known-map A* on a 0.1 m grid, heading feedback, and simulator pose. An RL-SAR TorchScript walking policy runs on the CPU at 50 Hz, producing targets for twelve joints. A torque-limited PD controller tracks those targets while MuJoCo advances at 200 Hz. Neither ROS 2 Nav2 nor Unitree's Sport API is part of these runs. The model responsible for mission exceptions is deepseek-flash through an ADK/LiteLLM host runner; it does not output joint actions. [1]

The approved mission envelope allows at most three exception judgments, a cumulative twenty simulated seconds of explicitly requested waiting, bounded replanning to the same destination, undelivered return, or operator attention. Rules validate response structure and bindings, then recheck fresh state, posture, contacts, cancellation, geofence, map revision, and remaining budget. A valid model response may still be refused if circumstances change.

For the moving-obstacle scenario, local control reads obstacle geometry and estimates velocity from previous observations. It checks projected conflict, requests yielding, verifies an observed stop, and resumes after a clear-path interval. The navigation controller receives no future obstacle trajectory. Nevertheless, simulator-truth geometry is a substantially easier observation problem than real camera or LiDAR perception. [2]

Both runs recorded simulated receipt, an empty terminal contact list, and no latched safety violation. They are different scenarios, not an Agent-on versus Agent-off comparison. Their times therefore cannot estimate the Agent's benefit or overhead. [1]

Moving obstacle: local yielding

The local controller issued two yields lasting 0.820 and 8.630 simulated seconds. Measured stopped states followed the requests after 0.470 and 0.460 seconds; the robot traveled 0.016884 and 0.015025 m during those intervals. This was not instantaneous stopping. A brief resumption between the yields should remain visible when assessing the release condition.

Moving-obstacle contact occurred on zero physics steps. Minimum center separation was 1.236451 m. Subtracting the declared 0.45 m robot radius and 0.24 m obstacle radius gives 0.546451 m of conservative-envelope clearance. That number is not foot-to-obstacle surface distance. The run completed without mission-level escalation or any LLM call.

Temporary closure: actual Agent decisions

The scenario closed both passages at 9.005 simulated seconds. At 11.005 seconds, the captured state showed no delivery route, an available return route, and a facility notice estimating reopening in about ten seconds. DeepSeek proposed a ten-second wait, admitted at 16.215 seconds. The passages reopened at 21.005 seconds, and a fresh observation after waiting found a delivery route. A second judgment proposed rerouting; Rules admitted it at 27.480 seconds. [1]

Outbound arrival at 53.130 seconds carried the second decision's identifier, linking judgment to an executed and verified navigation leg. Return and the final hold completed at 95.455 seconds. The failed first outbound attempt remained explicitly unverified rather than being overwritten. Host invocation intervals were 5.259115 and 1.090103 wall-clock seconds; these two observations are not a latency distribution or equivalent to simulator-side holding time.

4. Discussion

The system result is stronger than a transcript showing plausible model advice: the closure record links actual request and response hashes, Rules admission, a decision identifier, subsequent navigation, and terminal verification. At the same time, the zero-call moving-obstacle run demonstrates that local control retained responsibility for a short-horizon maneuver.

The facility notice makes the closure case interpretable but also constrains the claim. DeepSeek did not infer an unseen future through a world model. A simple rule using the same reopening estimate could choose to wait. Likewise, reroute means recomputing a path to the same approved destination; the action name alone does not prove selection of a long detour.

5. Limitations

One run per scenario establishes neither a general success rate nor a safety guarantee. Ground-truth pose and obstacle observations omit occlusion, detection failures, localization errors, and physical communication delays. Receipt is a logical simulated event; parcel handling, real people, and physical Go2 locomotion were not evaluated. No WAM, VLA, SimDist, or NavThinker benefit was tested.

The public videos render recorded physics at approximately three times playback speed. Video length, elapsed simulation time, and wall-clock inference intervals are different quantities. The public replay and verification scripts audit published records rather than independently reproducing the original simulator episodes. The source report's 2,715 passing tests, including 76 Go2 tests, supplement the runtime evidence; they are not substitute delivery trials. [1]

6. Conclusion

The Go2 records demonstrate a governed connection from bounded AI judgment to verified simulator navigation, simulated receipt, and return. They also show successful local yielding without invoking the LLM. A next performance experiment should compare Agent and rules decisions under identical closures, notices, observations, and action bounds, measuring whether meaningful improvement remains possible before expanding inference use.
